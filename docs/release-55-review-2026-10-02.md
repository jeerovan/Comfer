# Version 55 issue review — 2 October 2026

Firebase import 9: **76 groups / 198 events**, comprising **7 fatal groups / 37 crashes** and **69 ANR groups / 161 events**. Window: 24 September 03:42:10–2 October 03:51:34 UTC. Each group has a version-55 sample; all reported R8 map IDs in those selected stacks match the archived v55 mapping. Issue titles may retain older map IDs and are not used to choose the mapping.

## Changes and limits

- New fix for `46899b52662ccfe38b2ed305819cf25c`: delete/move callbacks stop safely when folder selection was cleared before recomposition. Valid selected-folder actions retain their existing behavior.
- Related defect reproduced by the deletion regression: the deleted folder remained in Room because saving the remaining folder map only upserts. Deletion now explicitly removes the selected ID with the existing DAO; other folder records are preserved.
- Retained the existing exact missing-accessibility-method fix and Huawei weather-widget namespace mitigation. The actual incomplete Pixel framework and Huawei provider are unavailable; device fixtures validate the guard, not production resolution.
- **73 other groups (4 fatal / 69 ANR) have no additional safe fix established from this evidence.** No blanket exception handlers, provider blacklist guesses, dependency upgrades, or UI-thread changes were made for these groups.
- Many samples omit frames, native symbols or the earlier stall. One sample per group does not establish every variant or a full ANR root cause. The isolated notificationTest app disables Firebase auto-initialization and does not exercise the production Firebase/Play license paths.
- Version 56 was subsequently rebuilt for the user's manual release on October 2. See [the release handoff](release-56-readiness.md) for current artifacts and validation; no Play publication has been performed. The September 30 artifacts are superseded.

## Validation

- App unit tests: **246 passed** after both production changes. Build-logic/ASM regressions: **13 passed**, freshly rerun through the parent Gradle build.
- **Emulator1, API 24:** final folder and app-list tests **11/11 passed** with English system language; focused folder test **1/1 passed** with Arabic system language. Existing bundled ANR/compatibility tests **29/29 passed** on the same folder-guard build before the persistence-only follow-up.
- **Pixel 10 AVD, API 37:** existing app-list tests **10/10 passed** after the persistence fix; final focused folder test **1/1 passed** under each English and Arabic system language. Existing bundled ANR/compatibility tests **31/31 passed** before the persistence-only follow-up.
- Folder tests exercise following system language, selecting that same language via the real language-picker trampoline, switching to the opposite language, and returning to system default. They check effective locale/direction, visible control bounds and same-language geometry, cleared-selection callbacks, repeated delete, persistent removal and preservation of another folder.
- Reproduction evidence retained: pre-fix null selection failed in a move callback at line 431 (the production crash retraces to the adjacent delete callback at line 481). After the null guard, the persistence assertion failed because the deleted Room row remained. Both assertions pass after their respective fixes.
- Initial harness failures are retained, not counted as passes: detached Compose test-node reuse and API-37 locale lookup/settling. The corrected harness reads LocaleManager for both system and app locales on API 33+ and refreshes test nodes after redraw. A standalone `-p buildSrc test` invocation lacked parent Gradle API dependencies; the correct parent-build command succeeded.
- Only the isolated `com.jeerovan.comfer.notificationtest` application was installed/modified. Effective system languages were restored to English. Emulator1's system-locales setting was returned to its originally absent value; Android now explicitly records `en-US` in its persistent locale property instead of its prior empty value. Pixel's system locale is `en-US` and the test app follows system default.
- No Test Lab quota used; no release published. No production ANR was reproduced or claimed fixed. OEM provider, incomplete API-34 framework, Firebase auto-init and Play-added license paths remain untested on these AVDs.

Evidence files include `folder-before.txt`, `emulator-5554-folder-en.txt` (persistence failure), `emulator-5554-folders-final-en.txt`, `emulator-5554-locale-final-ar.txt`, `pixel-folder-final-en.txt`, `pixel-folder-final-ar.txt`, the original combined-suite logs and `test-apk-sha256.txt` under the artifact directory below.
